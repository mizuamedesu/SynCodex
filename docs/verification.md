# Codex 実履歴の復元・巻き戻し検証

## 日本語入力: 2026-10-15

macOS の標準 nano（Pico）を疑似端末で起動し、`LC_ALL=C` では「続けて」の入力が制御文字として扱われて保存できず、`en_US.UTF-8` なら入力・保存できることを再現した。外部エディターの起動時にシステムの `locale charmap` で実際の文字コードを確認し、非 UTF-8 または無効なロケールなら利用可能な UTF-8 ロケールを子プロセスに渡すよう変更した。静的リンク版 SynCodex と、外部エディターが使う libc の違いもこの確認で扱う。

`tests/rewind_interactive.py` に、`LC_ALL=C`、存在しない UTF-8 ロケール、`locale` コマンドがない環境で「続けて」・複数行・日本語・絵文字を nano で入力・保存する検証を追加した。エディターが一時ファイルを書き込んでから非ゼロで終了した場合も、元の履歴を変更しないことを検証する。

## 巻き戻し: 2026-10-14

同日の追加検証では、別セッションを resume した **同じ Codex app-server を起動したまま** 未使用の会話を巻き戻した。別セッションへ `thread/metadata/update` を並行して 86 回送り、最新の Git branch メタデータが保持されること、使用中の対象の編集は拒否すること、編集した会話を同じ app-server で再開して新しい本文だけを取得できることを確認した。検証スクリプトは `scripts/live_rewind_e2e.py`。元の実履歴を新しい private home にコピーして使用し、元ファイルのハッシュは不変、認証ファイルのコピーと新しいモデル生成はなし。

macOS arm64、`codex-cli 0.162.1` で検証した。保存済みの実会話を新しい Codex home にコピーし、本文取得・再開によって表示用 SQLite を一度構築してから `rewind` を実行した。元の Codex home への書き込み・認証情報のコピー・モデルへの新しい生成ターンの送信は行っていない。コピー元ファイルの SHA-256 は検証前後で一致した。

| ケース | 巻き戻し前 | 巻き戻し後 | Codex による確認 |
| --- | --- | --- | --- |
| Assistant の途中発言を複数行の本文に編集 | 3 ターン、252 項目、19 発言 | 1 ターン、2 項目、2 発言 | `thread/read`・`thread/resume` 成功、編集した本文を取得 |
| 最初のユーザー発言を複数行の本文に編集 | 3 ターン、252 項目、19 発言 | 1 ターン、1 項目、1 発言 | `thread/read`・`thread/resume` 成功、編集した本文を取得 |
| 上記の元会話の最初のターンを参照する分岐を保全 | 1 ターン、163 項目、8 発言 | 1 ターン、163 項目、8 発言 | 元会話の巻き戻し後も `thread/read`・`thread/resume` 成功、件数を保持 |

分岐はコピーした実会話に対して `history_base` を設定して作成した検証用会話。元会話の編集時に独立した rollout に展開された。実データの検証では、`verify` の既定 `thread/list` フィルターには対象が出なかったため、一覧については SynCodex のローカル一覧・対話メニューを別途検証した。GUI の表示や新しい生成ターンは未検証。

対話操作は `tests/rewind_interactive.py` により、本物の疑似端末でセッション検索・発言選択・外部エディター保存、日本語／複数行、Esc／未保存による取消、編集中に対象が使用中になった場合の拒否を検証する。同日の画面改善では内蔵エディターの日本語・絵文字・複数行の貼り付け、元に戻す／やり直す、反映前の比較画面、比較から編集への戻り、破棄して発言一覧へ戻る操作、内部会話の表示切替、80 列の狭い端末、dry-run で履歴とロックを変更しないことも検証した。別セッションの追記・新規作成・共有 DB の更新を保持し、継承元の後続に未完成の行があっても frozen prefix を編集できることも検証する。Rust の `tests/rewind.rs` は圧縮／アーカイブ・圧縮前の DB パスからの現行 rollout 解決・旧形式・親子孫の分岐・入力履歴・DB 索引更新・復旧用データ・dry-run・不正入力・共有ロック・使用中の対象／分岐の拒否・入力履歴の既存 descriptor の保持を検証する。いずれも合成の履歴を使用する。

今回の実データ用の機械可読な結果は macOS の一時ディレクトリ内の `syncodex-rewind-live-*/` に保存した。実履歴を含むため Git の管理対象外。

標準エディターは nano に変更した。実際の nano を疑似端末で操作し、日本語／複数行の保存と巻き戻し、保存せず取り消した場合に元の履歴を保持することを確認した。`VISUAL=vim` / `EDITOR=vim` でも標準の nano を使い、`--vim` で明示的に Vim を選択できる。内蔵エディターは `--editor builtin` で引き続き利用できる。

## 復元: 2026-09-10

2026-09-10、`codex-cli 0.154.0`、Linux x86_64 で実施。

対象は SynCodex を開発している実際の会話 `01a0891b-fa94-7910-b149-0641a07c3a6c`。元の保存先は `/home/coder/.codex`、履歴形式は paginated。合成の会話データではなく、ユーザーの最初の依頼と、このアシスタントの返答を含むディスク上の履歴を使用した。

```sh
python3 scripts/live_e2e.py \
  --output backups/e2e-20260910 \
  --thread 01a0891b-fa94-7910-b149-0641a07c3a6c \
  --expect-text 'ここにcodexの履歴' \
  --expect-text '上流コードを調査し'
```

今回の会話は実行中のため、検証コマンドが走っている間の保存済み履歴を取得した。JSONL のコピー前後・SQLite 取得後に内容が変わっていないことを検査している。ただし未 flush の内容や、ここに記載した検証後の発言はこのスナップショットには含まれない。通常運用では Codex を終了してからバックアップ・注入する。

`resume` は実際の Codex エンジンによる履歴読み込み・再開初期化までを意味する。新しい質問へのモデル応答、GUI 表示、別 OS での作業ディレクトリ移行は検証していない。
